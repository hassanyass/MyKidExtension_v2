# Fuzzy — Chrome Extension (Manifest V3)

**Fuzzy** is the shipped name of the extension. `MyKid` remains the
repository and Python-package name.

Fuzzy blurs scary, gory and grown-up pictures and videos as a child
browses. Everything runs on the device — no image, URL or page content
ever leaves the browser (audited: `docs/12-privacy-and-limitations.md`).

**What it detects:** gore/violence and sexual content at the scene level
(whole-image blur), plus knives and scissors as regions. **What it does
not:** firearms, drugs, self-harm, hate symbols, or anything needing text
or audio.

**Detection accuracy on harmful content is unmeasured** — there is no
harmful evaluation set in this project. Safe fixtures only establish that
it doesn't fire indiscriminately.

## First-time setup

Two things the extension needs are intentionally **not** committed to git —
a 10MB+ model file and a third-party wasm runtime, both regenerable:

```bash
node apps/extension/scripts/setup.js
```

This copies `models/yolo11n.onnx` and `models/image-safety-classifier-xs.onnx`
from the project root into `apps/extension/models/`, and fetches the
`onnxruntime-web` wasm runtime into `vendor/`. Re-run it if either model or
the pinned `onnxruntime-web` version changes.

## What's here

| File | Purpose |
|---|---|
| `manifest.json` | MV3 manifest — content scripts, popup, background service worker, `offscreen`/`storage`/`alarms` permissions, `<all_urls>` host access, wasm-permitting CSP |
| `src/content/content-script.js` | The DOM layer, injected into every page. Discovers `<img>`/`<video>` elements via `IntersectionObserver` (only analyses what's actually visible) and `MutationObserver` (catches infinite-scroll/lazy-loaded content and SPA navigation), queues them for analysis, retries transient failures, and applies protection to whatever comes back flagged. Responds to the popup's `MYKID_GET_COUNTS`/`MYKID_RESCAN` messages. |
| `src/content/protection.js` | Renders and tracks blur/pixelate overlays for images — real re-rendered pixels, not CSS `backdrop-filter` (which fails silently in some stacking contexts). |
| `src/content/video-protection.js` | Frame-sampling protection for `<video>` elements: region-crop overlays, temporal persistence so blur doesn't flicker between samples, and reuse-detection for players (like YouTube) that swap source on the same element rather than creating a new one. |
| `src/inference/risk.js` | Port of the Python risk engine — turns raw model output (object labels, scene scores) into a protection decision. Kept in lockstep with `packages/risk/` via the cross-language parity tests in `tests/`. |
| `src/inference/detector.js`, `src/inference/scene-classifier.js` | Preprocessing/postprocessing for the two on-device models (see below). |
| `src/inference/protection-render.js` | Draws the actual blur/pixelate output onto a canvas for `protection.js` to display. |
| `src/background/service-worker.js` | Thin router: ensures the offscreen document exists, relays analysis/self-test requests to it, keeps the toolbar badge in sync with the on/off state, and runs a `chrome.alarms` keep-alive (see **Troubleshooting** below). Does **not** run inference itself — onnxruntime-web needs dynamic `import()`, which the HTML spec disallows inside a service worker. |
| `src/offscreen/` | Hidden extension-owned page where onnxruntime-web and both models actually load and run: `image-safety-classifier-xs` (cheap gate — gore/sexual/safe scene classification, runs on every image) and `yolo11n` (object detector for knives/scissors, runs only when the cheap gate doesn't already rule the image safe). A normal DOM/Window context (unlike the service worker) that still runs under the extension's own CSP (unlike a Worker spawned from the content script, which real sites' CSP can block — hit this on youtube.com). See `docs/11` for the full debugging trail that led here. |
| `src/shared/config.js` | Loads the on/off toggle, per-category switches, and practice-mode overrides from `chrome.storage.local`. |
| `src/popup/` | The toolbar popup a parent (and, deliberately, a curious child) sees: on/off switch, per-category toggles (gore, weapons — sexual-content detection is always on and not exposed as a switch), live counts of what's been checked/hidden on the current page, and a "Grown-up settings" section with practice mode and a self-check button. |
| `vendor/onnxruntime-web/` | *(gitignored, generated by setup.js)* wasm-only onnxruntime-web build — single-threaded by design, since multi-threaded wasm needs cross-origin isolation headers this extension can't guarantee on arbitrary sites. |
| `models/` | *(gitignored, generated by setup.js)* copies of the two `.onnx` models from the project root — extensions can't reference files outside their own loaded folder. |
| `assets/icons/` | The Fuzzy mascot, at 16/48/128px. |
| `devtest/` | Standalone HTML harnesses for exercising the content script and video protection without a full browser install — see `devtest/README.md`. |

## Load it locally

1. Run the setup step above if you haven't already
2. Open `chrome://extensions`
3. Enable **Developer mode** (top right)
4. **Load unpacked** → select this `apps/extension/` directory
5. Open any normal webpage (not `chrome://`) and click the Fuzzy toolbar icon — the popup should open showing on-page image/video counts and a status message

If the popup says "Fuzzy cannot look at this page," that's expected on `chrome://` pages, the Web Store, and any tab that was open *before* you loaded/reloaded the extension (content scripts only attach on page (re)load — refresh the tab).

For a live self-check of the detection pipeline, open the popup's "Grown-up settings" and click "Run a quick self-check."

## Troubleshooting

**Toolbar icon does nothing — no popup opens at all, on any page.**
Check `chrome://extensions` → Fuzzy card → "service worker." If it shows
**Inactive**, that's normal on its own (Chrome idles MV3 service workers
after ~30s); the popup doesn't depend on the service worker being awake.
But if the popup genuinely won't open anywhere, the extension's background
context may be wedged — a known Chromium bug where a long-idle MV3 service
worker occasionally never wakes again, including for toolbar clicks
([tracking bug](https://issues.chromium.org/issues/40733525)). A one-minute
keep-alive alarm in `service-worker.js` mitigates this, but if it still
happens: **Remove** the extension on `chrome://extensions` and **Load
unpacked** again, rather than just clicking reload. If you see "Service
worker registration failed. Status code: 15" in the extension's error log,
that means something threw during the service worker's top-level script
evaluation — check that log for the actual error.

**Analysis never finishes / nothing ever gets blurred on a page that should
trigger it.** Open "Grown-up settings" in the popup — the technical panel
there (checked/skipped/failed counts, last error, peak scores) is built
specifically to distinguish "nothing harmful found" from "analysis isn't
running at all." A failed count that never climbs to the retry limit is
usually the offscreen document still warming up its two model sessions.
